Benchmarks

How tsdb 0.9.0 compares with eleven other databases on the same machine and the same data. Every number here comes from the published 0.9.0 results.

How it was measured

  • One machine: AMD Ryzen 9 7950X (16 cores, 32 threads), 64 GB RAM, NVMe disk. One system at a time; every server in a container with the same hard memory limit of 48 GB (InfluxDB 2: 24 GB, and it used at most 8.3 GB).
  • The data: 100 sensors with 1 million readings each, 100 million readings in all, from seven kinds of sensors that behave like real ones (temperatures that creep, tanks that fill and drain, a fast vibration sensor, flows with shutdowns). The size test adds 23 real sensors from a hydraulic test rig: 31 data sets.
  • Every answer was checked against tsdb's before it was timed. Every timing was repeated 5 times; a time is the median time of one request. tsdb ran as a server, over TCP.
  • We left out the questions tsdb answers from the summaries it stores, such as a count over all the data: they measure a lookup, not reading data. Every question below reads the data.
  • A system that ran out of memory or refused a request is shown with the reason. That is a result, not a missing number.

Size on disk

The raw data takes 12 bytes per reading (8 for the time, 4 for the value). tsdb stores the 100 million readings in 114 MB, about a tenth of that.

Many clients at once

With 32 clients each asking about 100 sensors at once, some systems ran out of memory or refused requests. tsdb never used more than 2.2 GB.

100 billion readings

Hours cut through nearly every block of 8192 readings, so both systems read the data; tsdb is 2 to 3 times faster.

Inside your program

chDB is ClickHouse as a library. DuckDB got its readings sorted beforehand, which made its job easier (not counted).

Measure it yourself

Clone the repository and run tools/bench-tsdb.sh --quick first to see that it works. It builds an optimized copy, runs tsdb's own benchmarks several times and writes a summary with the mean and spread of every number. The comparison with the other databases is in bench/dbcmp; every single measurement is in 0.9.0-tables.md.
