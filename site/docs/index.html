What tsdb is

tsdb is a small, fast time series database written in C. It stores readings from sensors, one series per sensor, and gives them back by time range: as raw points, or as summaries such as the average of every hour.

Why it exists

At IntelliStream we work with industrial data: sensors on pumps, tanks, pipelines and machines that report a value every second or every minute, for years. Our DataHub platform first stored this data in ClickHouse. ClickHouse is a general analytics database, and time series are only one of the many things it has to be good at. So we wrote a database that does nothing but time series. It keeps the best ideas of ClickHouse's storage design (MergeTree) and adds ALP-style compression for the sensor values.

We built it to:

  • store that data for less money: about a tenth of its raw size, and less than half the disk ClickHouse needs for the same data;
  • cost less to run: one small program that works well with its defaults, and no cluster to look after;
  • answer time series questions faster: "the 5-minute averages of this sensor yesterday" takes 0.09 ms.

Two ways to use it

As a library, inside your program
Link libtsdb.a into a C program, or use the embedded mode of the Rust, Python or Java clients. The database is a directory on disk. There is no server and no network.
As a server, tsdbd
Run tsdbd and talk to it over TCP from C, Rust, Python or Java. One server answers many clients at once.

What it is not

  • It is not a SQL database. There are no tables and no joins. You ask for a series and a time range.
  • It has no login and no encryption yet. Run it on a trusted network only. See SECURITY.md.
  • It is still young. Version 0.9.0 is the first release. Until 1.0, a new 0.9.x version may not open the files of an older one; you then move your data with export and import.

What it can do

  • Values can be float32, float64, int64, bool or a state (a text label from a small set, like "running"). Any value may be missing (null). Times are in milliseconds.
  • Writing a value for a time that already exists replaces it. You never get duplicates back.
  • Read raw points, or summaries per time bucket: fixed buckets (every 5 minutes) or calendar ones (day, week, month, quarter, year) in your time zone.
  • Downsample a series for a chart (LTTB), get the spread of each bucket, and time-weighted averages.
  • Delete or replace the values of a range, and let old values expire with a retention period.
  • Ask about many series in one request, all read at the same instant.
  • Safe writes: data is on disk when a write returns.
  • One writer and any number of read-only followers can share a directory, also over NFS.
  • An Apache Pulsar 5 sink writes points from Pulsar into tsdb.

Concepts explains each of these.
