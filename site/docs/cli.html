Command line

tsdb works on a database directory directly, with no server. Use it to load files, look at data, take backups and change settings.

Every command starts with the database directory: tsdb DIR COMMAND .... Run build/tsdb without arguments for the full list, the time formats and the groups. The quick start uses import and query. tsdb DIR user manages the users who may log in to tsdbd.

Commands

CommandWhat it does
insert SERIESreads time,value lines from standard input into one series
import [FILE]reads series,time,value lines, or an export file (see backup). New series are float32; an empty value or null is a null
export [-o FILE]writes all series, or those matching --series PATTERN, in a time range with --from and --to; also while tsdbd runs
query SERIES START END [what] [group]raw points, or count, sum, min, max, avg, all, range, stddev_pop, stddev_samp, var_pop, var_samp per group
query SERIES START END lttb NN points that keep the shape of the line, for charts
query SERIES START END twa [group]time-weighted average; --linear for straight lines between readings, --max-gap INTERVAL for the longest silence that still counts
create SERIES [PATH] [--type T]creates a series of type float32, float64, int64, bool or state, in volume PATH if given
serieslists the series with their type and volume
volume add PATH, volume listadds or lists volumes
statsrows, parts, size and compression ratio
partslists the parts (the files the data is in)
optimizemerges every partition into one part
drop-before TIMEdrops whole partitions that end before TIME
delete SERIES START ENDdeletes the series' values in [START, END)
retention SERIES [AGE|off]shows or sets how long the series keeps values, such as 30d or 12h; off keeps them for ever
user ...adds, changes and lists the users who may log in to tsdbd; see below

Users

tsdbd lets in only clients that log in, and it does not start until the database has a superuser, a user who may do everything. tsdb DIR user changes the file USERS in the database directory. It works while tsdbd runs: the server sees a change within a second.

CommandWhat it does
user add NAME [--superuser]adds a user, a superuser with --superuser; it asks for the password
user passwd NAMEsets a new password
user drop NAMEremoves a user; its open connections are closed. Dropping the last superuser only warns, but tsdbd then does not start again until there is one
user alter NAME --superuser|--no-superusermakes a user a superuser or takes that away
user grant NAME RIGHTS SELECTORgives rights on the series the selector matches
user revoke NAME RIGHTS SELECTORtakes them away again
user listlists the users with their rights
user compactrewrites USERS with only what is current: every change is added at its end, so the file grows
  • Rights: read, insert, delete, admin, and write for insert and delete; several with commas, such as read,insert.
  • Selectors: all; prefix:acme/, the names that start with acme/; name:pump7.flow, one series; glob:acme/*/temp?, the names the pattern matches (* is any text, ? one byte, \ takes the next byte as it is). A series a user may not touch answers like a series that does not exist.
  • Passwords are never taken from the command line, where other users could see them: --password-file FILE reads the first line of FILE, else the variable TSDB_PASSWORD, else tsdb asks without showing what you type.

A user for a collector that may only add data under acme/:

build/tsdb /data/sensors user add acme/ingest --password-file /etc/tsdb/acme-ingest.password
build/tsdb /data/sensors user grant acme/ingest insert prefix:acme/
build/tsdb /data/sensors user list

A user with admin on a prefix manages the users whose names start with it. It does that through a running tsdbd, so it needs no access to the server's files: add --server HOST:PORT --login NAME (the login's password comes from --login-password-file FILE, else TSDB_LOGIN_PASSWORD, else the terminal). tsdb user whoami --server HOST:PORT --login NAME shows that user's rights.

build/tsdb /data/sensors user add acme/admin --password-file /etc/tsdb/acme-admin.password
build/tsdb /data/sensors user grant acme/admin admin prefix:acme/
# from any machine that reaches tsdbd, as acme/admin (it asks for acme/admin's password, then the new one):
build/tsdb user add acme/dashboard --server db1:7070 --login acme/admin
build/tsdb user grant acme/dashboard read prefix:acme/ --server db1:7070 --login acme/admin

Query options

  • --desc: newest first.
  • --limit N: at most N rows or buckets. With --desc, "the last 10 hours" reads about 10 hours of data.
  • --tz ZONE: calendar groups in a time zone, such as Europe/Oslo. The default is UTC.

Times and groups

  • Times: 1700000000000 (milliseconds), 2024-01-31, "2024-01-31 12:00:00.250", 2024-01-31T12:00:00Z, now, now-1h, min, max. A range is [start, end).
  • Fixed groups: 500ms, 10s, 15m, 6h.
  • Calendar groups: 1d, 1w, 1mo, 1q, 1y, in the zone of --tz.

The output is tab-separated text, as ClickHouse's client prints it, with times in UTC. After the rows it prints how many there were, how long the query took and what it read.

An example

Steps 3 and 4 of the quick start load a day of readings and ask for them in three ways:

# 3. Put it in a database. A database is just a directory; tsdb creates it.
build/tsdb /tmp/tsdb-qs/db import < /tmp/tsdb-qs/rows.csv

# 4. Ask for it: the first 3 rows, the average of every hour, and a summary of every day in Oslo.
build/tsdb /tmp/tsdb-qs/db query pump7.flow 2024-06-01 2024-06-02 raw --limit 3
build/tsdb /tmp/tsdb-qs/db query pump7.flow 2024-06-01 2024-06-02 avg 1h
build/tsdb /tmp/tsdb-qs/db query pump7.flow 2024-06-01 2024-06-03 all 1d --tz Europe/Oslo
