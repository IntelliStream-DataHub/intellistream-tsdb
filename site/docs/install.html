Install and build

tsdb is built from source with make. To run it on another machine, build the portable tarball and copy it over.

The packages you need

You need a C compiler (C11), make, libzstd, and liburing for the server. Python 3 is used by some of the tests.

Debian or Ubuntu

sudo apt install build-essential libzstd-dev liburing-dev python3

Fedora, RHEL or AlmaLinux

sudo dnf install gcc make libzstd-devel liburing-devel python3

On RHEL or AlmaLinux, if liburing-devel is not found, enable the CRB repository (sudo dnf config-manager --set-enabled crb). Or leave liburing out and build with make NO_URING=1: io_uring is disabled by default there anyway, and tsdbd then uses epoll.

The Rust, Python and Java clients need their own tools on top: cargo, python3 and mvn. Clients says which.

Build

Run make in the top directory of the checkout. Everything lands in build/:

FileWhat it is
build/tsdbdthe server
build/tsdbthe command-line tool
build/libtsdb.athe database as a C library; link with -lzstd -lpthread -lm
build/libtsdbclient.athe C client of tsdbd; link with -lzstd -lpthread -lm

A few variants:

  • make builds for the CPU of this machine (-march=native).
  • make PORTABLE=1 builds without -march=native.
  • make NO_URING=1 (after make clean) builds tsdbd for epoll only, so liburing need not be installed.
  • make test runs all unit, crash-recovery and server tests.

The portable tarball

make builds for this machine's CPU. To run tsdb on another one, AlmaLinux 10 for example, build a portable tarball and copy it over:

make dist       # build-dist/tsdb-VERSION-x86_64-linux.tar.gz

It runs on any x86-64 Linux with glibc 2.34 or newer and an x86-64-v2 CPU (Intel Nehalem, Sandy Bridge and later; AMD Bulldozer and later). zstd and liburing are linked in, so nothing else is needed. The code that packs and unpacks values is in it three times, for x86-64-v2, v3 (AVX2) and v4 (AVX-512); tsdbd picks the best one at startup. Every level writes the same bytes and gives the same answers, so data moves freely between machines.

The tarball holds bin/tsdbd, bin/tsdb, the two libraries and their headers, its own test suite and a systemd unit. To install it as a service:

tar xzf tsdb-VERSION-x86_64-linux.tar.gz && cd tsdb-VERSION-x86_64-linux
tests/run-tests.sh /var/tmp            # optional, a few minutes
install -m 755 bin/tsdbd bin/tsdb /usr/local/bin/
restorecon -v /usr/local/bin/tsdbd /usr/local/bin/tsdb    # SELinux: bin_t
useradd -r -s /sbin/nologin -d /var/lib/tsdb tsdb
install -m 644 systemd/tsdbd.service /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now tsdbd

The unit runs tsdbd on 127.0.0.1:7070 with its data in /var/lib/tsdb. Running tests/run-tests.sh is optional and takes a few minutes. make dist-check-almalinux10 runs the tarball's tests in an AlmaLinux 10 container with Podman.

On AlmaLinux and RHEL 10, io_uring is disabled by default. tsdbd notices and uses epoll by itself (--io auto, the default), and says so when it starts.
